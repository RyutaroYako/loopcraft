# エージェント向け DX の記録

CLI の使い方を変えたら、コーディングエージェントに同じタスクを解かせ、変える前と比べます。エージェント自身の報告では採点せず、できたファイルをスクリプトで確かめます。

## 測り方

```bash
vp run -r build
(cd apps/cli && pnpm pack --pack-destination ../../tmp/packs)
node scripts/agent-dx/run.ts --tarball tmp/packs/loopcraft-0.2.0.tgz --label after --runs 5
```

- `--label` ごとに `--out`（既定は OS の一時ディレクトリの `loopcraft-agent-dx`）の下に `<label>/` を作り、パックした CLI を入れた空のディレクトリで `claude -p` を走らせます。手元の設定・MCP サーバー・`serve`（ブラウザを開いて終わらない）は使わせません。
- タスクは `scripts/agent-dx/tasks.ts` にあります。採点は `scripts/agent-dx/score.ts` で、比べる CLI の版によって基準が動かないよう、`@loopcraft/core` は使いません。
  - **create**: 文章から図を作る。変数どうしが重ならず、矢印が変数を突き抜けない配置にする
  - **extend**: 既にある図に変数と関連を足し、できたループに注目する。ほかは変えない
  - **tidy**: 変数が重なった図の配置を直す。構造は変えない
- `--out` を変えるときもリポジトリの外にします。リポジトリの中だと、ルートの `package.json` の `devEngines`（pnpm）に `npm init` が引っかかって止まります。
- 結果は `results.jsonl` に 1 回ずつ追記し、最後に表を出します。数えるのは、成功した回数・ターン数・コスト・出力トークン・Bash の呼び出し・loopcraft の呼び出し・`--help` を読んだ回数・スクリプトを書いた回数です。

## 2026-11-06: 自動配置を stress majorization に替える

### Experiment

- 比べたもの: `layout-before`（0.3.0。main の版）と `layout-after2`（下の Changes を入れた版）。
- 条件: Sonnet、`create` と `tidy` を 5 回ずつ。`extend` は、座標の無い変数を足すだけで、置き方の変わらない経路なので測っていません。

### Findings

|              | 成功 | ターン | コスト | 出力トークン | Bash | loopcraft | help | 残った警告 |
| ------------ | ---- | ------ | ------ | ------------ | ---- | --------- | ---- | ---------- |
| create（前） | 5/5  | 4.8    | $0.07  | 1747         | 2.6  | 2.6       | 1.0  | 0          |
| create（後） | 5/5  | 5.0    | $0.07  | 1834         | 2.6  | 2.6       | 1.0  | 0          |
| tidy（前）   | 5/5  | 5.6    | $0.07  | 1182         | 3.0  | 2.4       | 1.0  | 1          |
| tidy（後）   | 5/5  | 5.2    | $0.06  | 826          | 2.8  | 2.6       | 1.0  | 0          |

- 「残った警告」は、エージェントが初めに打った `layout --all` の後の `check` で出た警告の数です（5 回とも同じでした）。
- **`tidy` で `layout --all` の後に警告が残らなくなった。** 前は 5 回とも、矢印の交差の警告が 1 件残り、直そうとして座標を書き換えた回がありました（5 回のうち 1 回。Bash は 6 回）。後は 1 回の `layout --all` で警告が無くなり、出力トークンが 3 割減りました。
- **警告が残ると、エージェントはそれを手で消そうとする。** 途中の版（変数をまわりの空いた所へ動かす処理を入れる前）では、見本の図に交差が 1 件残り、5 回のうち 1 回で、`教育コスト` の座標を 13 通り試してから元に戻していました。避けられる交差を残さないことが、手間に直に効きます。
- `create` は前後で差がありません。エージェントが自分で座標を決めることが多く、`layout` に頼る場面が少ないためです。

### Changes

- 配置の計算を、力学モデル（Fruchterman–Reingold）から stress majorization に替え、ループの変数を輪の形に並べるようにしました。
- 一から組んだ並びと、今の位置から整えた並びを比べ、崩れが同じなら今の並びを残すようにしました。`layout --all` は、組み直しても崩れが減らなければ図を変えません。
- 交差や突き抜けに関わる変数を、近くの変数と入れ替えたり、空いた所へ動かしたりして減らします。残った突き抜けは、矢印を曲げて逃がします。
- ループの記号を、名前の文字も含めて、変数と矢印から離して置くようにしました。内に空きの無い細長いループでは、外のすぐそばに置きます。
- 決まった図の一式で配置を比べる `scripts/layout-bench/run.ts` を足しました。前後の合計は、突き抜け 23 → 0、交差 73 → 44、ループの記号の重なり 3 → 0、40 変数の図で 450〜560ms → 110〜150ms です。
